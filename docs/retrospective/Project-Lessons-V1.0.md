面向个人英语学习者的原生 Android「碎片时间播放器」：刷牙 2 分钟、滴眼药水 3 分钟等场景，一键从上次位置播放本地英语音视频并倒计时；到点停媒体、保存进度、只提醒一次。包名 `com.wanghoufan.fragmentplayer`，APK 侧载，V1 完全离线。

## 4. 发现的真实问题（如实标注，不圆）

### D1 交接文档与 Git 事实冲突，靠「补记提交」追平

`docs/handoff/HANDOFF.md` §1 写「当前 Task：0.2.8 已构建、真机 8 项 PASS、四机同包；**代码未提交**」，而 Git 显示 `a74c823` 已在 2026-11-13 提交并推送。此后连续两个提交（`130d713`、`ecffad2`）都只是在补记「已推 main」。

- 后果：任何人在 11-13 当天读 HANDOFF，会以为代码还在工作区；实际已在远端。
- 根因：交接文档的「现势」字段靠人写，提交动作发生时没有人回写。
- 这不是本项目独有，是跨项目共性问题（见送审包 §跨项目共性问题）。

### D2 两份文档对「当前版本」说法不一致

- `VERSION.md`：0.2.8(21)
- `docs/architecture-facts.md`：开头「最后核对：2026-11-11」，正文写「当前版本：**0.1.9 / versionCode 10 为最终构建**」

两份都是「当前版本」口径，差了 9 个小版本。`architecture-facts.md` 的核对日期停在 11-11，之后 0.2.0~0.2.8 全部未回写。

- 判定：**文档过期**，不是版本台账错。按中央规则，版本真源是 `009-软件管家/版本台账.md` §H，`VERSION.md` 是指针，`architecture-facts.md` 只是派生描述且未跟上。

### D3 验收矩阵未跑满就对外表述

`docs/risks.md` R2 明确写「只凭前台 2 / 后台 2 / 锁屏 4（共 8 轮）就宣布到点可靠」，并要求「报告里固定写 8/10，不得写全通过」。这条风险自述很诚实，但也说明**验收口径曾经被放宽过**。

### D4 真实素材前提不足，样本验收与真实验收混用

`docs/risks.md` R1：Note 11 上真实素材仅 1 节，其余 7 节为合成样本。AC06 的通过结论主要靠 Note 12T Pro 的 13 节真实 MP3。这条已被自己识别并限定引用范围，属**已识别未消除**。

### D5 正式产品计划不在治理约定位置

`docs/pm/` 下只有 `PLAN.template.md`、`PRODUCT_PLAN.template.md` 两个模板；真正的产品计划在 `docs/plan/P069-Fragment-Learning-Product-Plan-V1.1.md`。`HANDOFF.md` §1 自陈「docs/pm 尚无正式 PRODUCT_PLAN，不计 ORCA Gate」。

- 判定：**治理口径让步于现实**。项目自己知道，也写明了，属可接受但需登记的口径偏差。
