## 1. 高影响

### R17 0.2.8 dirty 包不可签收（已被 0.2.9 替代）
- 影响：0.2.8 无法对应功能提交，同 vc 干净重建 SHA 不同；仅作历史证据。
- 处置：0.2.9(22) 已由功能提交 `5cf5842` 干净构建并登记；0.2.8 不再作为任何验收对象。

### R18 锁屏首屏看不到到点通知（0.2.10 已修应用侧，展示仍受机型限制）
- 影响：熄屏时用户可能只听到铃声，看不到「哪节课结束/该切换了」。
- 触发：2026-11-14 Note 12 Pro 锁屏首屏只见其他 App 媒体卡与 USB 通知。
- 处置：0.2.10 已把到点通知从 Silent 分区改到 Alerting（`timer_alert_v3` 挂 0.1s 静音音频、去掉 `setSilent`）。
  Note 12 Pro 本机**连系统 shell 发的对照通知也不上锁屏**，属设备/ROM 行为；换机或在 MIUI 开启锁屏通知后复测，见 R22。

### R1 Note 11 真课只有 1 个完整视频（AC06 已由 13 节真实素材覆盖）
- 影响：Note 11 单机样本仅 1 节；机制结论已由 Note 12T Pro 13 节真实 MP3 支撑。
- 处置：引用 AC06 须写明证据来自 12T Pro 13 节；源目录 5 个 `.baiduyun.p.downloading` 是未下完临时文件，不计课程。

### R2 AC08 到点矩阵只完成 8/10
- 影响：前台/后台/锁屏的按秒到点与通知到达率没有统计结论，OEM 省电/勿扰下可能延迟或静默。
- 触发：只凭前台 2 / 后台 2 / 锁屏 4（共 8 轮）就宣布到点可靠。
- 处置：按前台/后台/锁屏各 10 轮补齐，记录每次延迟与失败数；报告里固定写「8/10」，不得写全通过。

### R6 旧机（Note 11 / Android 11）锁屏依赖发声权限
- 影响：该机开权限后可见；结论不可外推到 Android 14/15（见 R22）。
- 处置：交付说明只写「部分机型/系统版本可见」，不得写「无条件可见」。

### R3 debug 签名，不可作为发布包
- 影响：不能上架或正式分发；升级/覆盖安装受签名策略约束。
- 触发：把 debug APK 当正式版交付或换机安装。
- 处置：发布前生成正式签名并登记版本台账；当前 0.2.8 仍 debug 侧载，且 dirty 来源，不可发布。

## 2. 中影响

### R19 精确闹钟未授权时到点可能延后
- 影响：Android 12+ 默认 deny 时退化为 `setAndAllowWhileIdle`（本机窗口约 90s），长时 Doze 可能晚几分钟。
- 触发：`SCHEDULE_EXACT_ALARM granted=false`；设置页已显示「准时提醒 未允许 / 去授权」。
- 处置：当前靠 ticker + `PARTIAL_WAKE_LOCK` 兜底；授权后补 3/10 分钟锁屏轮，不承诺 100% 按秒。

### R4 备份只验证到「单机 UI 往返」，双机/换机恢复未测
- 影响：换机时可能选不到文件或导入失败，而文档看起来「备份已通过」。
- 处置：系统选择器选 JSON → 导入 → 数据回读已 PASS（§19；本轮再验 2/0/21）；写结论保留「未做双机恢复」限定。

### R5 AC09 已修复，但其余中断场景未验证
- 影响：来电、耳机拔出、系统重启后的断点恢复与提示仍无证据，用户可能误以为仍在学习或断点丢失。
- 触发：把 AC09 的强停首屏横幅 PASS 外推到所有中断场景。
- 处置：强停/杀进程链路已由 0.1.8 根级横幅真机 PASS、0.1.9 继承；来电、耳机拔出、系统重启恢复另列未测，补测前不得写全项 PASS。

- **锁屏可见性（旧机）**：Note 11/Android 11 开发声权限后可见且有闹钟音（`build/qa/104-lock-alert-visible.png`）；不可外推到 Android 14/15，见 R22。

### R7 OEM 省电 / 勿扰 / 通知默认为忽略
- 影响：到点提醒延迟或静默，甚至进程被杀导致计时中断。
- 触发：MIUI/OPPO 省电策略、勿扰模式、新装应用通知默认「忽略」。
- 处置：Note 11 通知已可用、精确闹钟在 Android 11 无需权限；OPPO 实测默认忽略通知已手动打开；勿扰与省电专项未测，不得承诺 100% 按秒到点。

### R8 MIUI 文件选择器文件卡/文件夹卡对 `input tap` 无响应
- 影响：自动化验收会在 SAF 目录选择与备份 JSON 选择处假失败（按钮与滑动正常，卡片不响应），被误记成产品缺陷。
- 触发：用裸 `adb shell input tap` 点 DocumentsUI 文件夹卡片或文件卡片。
- 处置：改用 UiAutomator 无障碍 `ACTION_CLICK`（`PickFolderTest` 已成功完成目录选择）；测试 APK 用完卸载，避免双进程干扰。此条属测试通道限制，不是 App 缺陷。

### R9 装机版本不齐（AC11）
- 影响：Note 12 Pro 已装 0.2.10(23)，Note 11T Pro+ 为 0.2.9(22)；OPPO 仍 0.2.8、Note 11T Pro 仍 0.2.7(18)。
- 处置：发布前逐台回读 versionName/Code 与 SHA，或由用户明确接受单机验收；清单见 `docs/qa/evidence-2026-11-14-regression/logs/device-inventory-2026-11-14.txt`。

### R21 返回键页面栈（已修，0.2.9）
- 处置：`resolveBackAction` 已实现非计时 Tab 回计时、完成页回 IDLE、其余双击退出；Android 15 与 Android 14 真机 BACK 复测均 PASS，单测 3 条。

### R22 锁屏首屏不展示到点通知（Android 14，权限全开）
- 影响：用户锁屏时只听到铃声，看不到「哪节课结束」。
- 触发：Note 12 Pro 允许通知/锁屏/发声/振动全开、勿扰关；0.2.9 记录 `sound=null groupKey=silent` → Silent 分区。
- 已修：0.2.10 改为 Alerting（实测 `mIsInterruptive=true`、渠道带 USAGE_ALARM 音源、到点 +0.3s 创建）。
- 现况：0.2.10 下该机锁屏首屏仍不可见，但**同机 `cmd notification post` 对照通知同样不可见** → 设备/ROM 只渲染媒体卡与 USB 常驻通知。
- 处置：本机不能作为「锁屏可见」正向验收机；换机或用户开启 MIUI 锁屏通知后复测，在此之前不得写「锁屏可见已通过」。

## 3. 低影响 / 观察项

### R20 真实课程素材（已纠正）

- 处置：0.2.9 已补测播放/断点/锁屏有声；自动下一节与无音轨提示仍未测。

### R23 验收机前提：先确认该机锁屏会渲染第三方通知
- 影响：锁屏首屏类 AC（AND-007、AC-08 锁屏可见）在「不渲染第三方通知」的机器上永远测不出 PASS，也测不出真实 FAIL。
- 触发：Note 12 Pro 锁屏只显示媒体会话卡与 USB 常驻通知；用 `cmd notification post` 发对照通知同样不出现。
- 处置：做锁屏类验收前，先发一条应用外对照通知确认机型前提；前提不成立就换机或记 BLOCKED，不得把 ROM 行为写成产品缺陷。

- **R10 Media3 合并注入 `ACCESS_NETWORK_STATE`**：项目未声明 `INTERNET`，合并清单仍出现网络状态权限；本轮未动。

- **R12 AC05 拖动进度/播完自动下一节、AC10 场景编辑与删除未逐项验收**：代码存在，判据未覆盖（AC02 跨场景断点、AC05 切课不重置、AC07 飞行模式已由 T069-18 补测 PASS）。
- **R13 提醒铃声与震动只在提醒音量 8 下验证**：Note 11 媒体音量 8 时到点有声；静音/勿扰/闹钟音量为 0 的场景未测。

- **R15 样本与截图在 `build/`**（不入库）：清理构建目录会丢失复跑素材；本轮证据已另存 `docs/qa/evidence-2026-11-14-regression/`。
